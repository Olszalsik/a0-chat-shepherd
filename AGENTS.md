# chat_shepherd

> Continuously watches your chats, auto-nudges stalled agents back to work, and flags chats that need human input. Glanceable dashboard with per-chat status icons.

**Version:** 1.0.0 · **Plugin ID:** `chat_shepherd`

## Purpose

Agent monitoring: a `job_loop` extension ticks periodically, classifies every live `AgentContext` into one of 8 statuses (`running / stalled / nudged / intervention / awaiting_user / error / paused / idle`), auto-sends a nudge `UserMessage` to stalled chats (bounded by `max_auto_nudges` + `nudge_cooldown_minutes`), raises a HIGH-priority OS notification when a chat exhausts its nudges, and keeps per-chat state + a 50-entry action history in `data/state.json`. The WebUI sidebar (JS in `sidebar-chats-list-start`) shows a per-chat status icon via `GET /api/plugins/chat_shepherd/status`, with manual nudge / resolve / dismiss actions.

## Ownership / Layout

- `extensions/python/job_loop/_30_chat_shepherd.py` — `ChatShepherdTick(Extension)`; calls `helpers.monitor.tick(cfg)` synchronously each loop iteration (guarded, respects `enabled`).
- `helpers/monitor.py` — `classify_chat()` (pure classifier: paused → running → error.txt → last-log-type → idle-minutes ladder) + `tick()` (state mutation, auto-nudge via `context.communicate(UserMessage(NUDGE_TEXT))`, intervention notification via `helpers.notification.NotificationManager`, nudge-counter reset when a chat runs/answers/pauses).
- `helpers/state.py` — JSON persistence at `usr/plugins/chat_shepherd/data/state.json` (`{chats: {chat_id: entry}, history: [50-ring], last_tick}`); defensive `default_state()` on any parse failure.
- `helpers/constants.py` — `PLUGIN_NAME`, status string constants, `NUDGE_TEXT` (the auto-nudge prompt), `HISTORY_LIMIT`.
- `api/status.py` — `Status(ApiHandler)`; live re-classification per request (state.json is treated as stale by design — fixed the stuck ⏸️), persisted-only chats re-derived to `error|idle`, sorted by severity, counts + last 20 history items.
- `api/nudge.py` — `Nudge(ApiHandler)`; manual nudge (`chat_id`, optional `text`) via `AgentContext.use(chat_id).communicate(...)`; bumps `nudge_count`, writes history.
- `api/resolve.py` — `Resolve(ApiHandler)`; `action=resolve` resets a chat to `awaiting_user` with nudge count 0; `action=dismiss` deletes the state entry.
- `api/config.py` — `Config(ApiHandler)`; empty body = read, else sanitize (bool/int coercion + clamps: stall 1–240, nudges 0–20, cooldown 1–240; icon strings ≤16 chars, known status keys only) and persist via `save_plugin_config`; merges its own `_DEFAULTS` under `config.json` for this endpoint.
- `webui/` — `config.html` (settings modal), `main.html` (dashboard), `shepherd-sidebar.js`/`shepherd-store.js` (sidebar chips), `shepherd-init.html` (webui extension in `sidebar-chats-list-start`), `thumbnail.png` (generated by `scripts/gen_chat_shepherd_thumbnail.py` — gold crook + cream flock).

## Local Contracts

- **Extension point**: `job_loop` fires on the framework's periodic loop; the extension is a `helpers.extension.Extension` subclass with `async execute(**kwargs)` — plain functions are never loaded (see [[extension-synthetic-class-gotcha]]).
- **Plugin config**: `plugins.get_plugin_config('chat_shepherd')` falls back to `default_config.yaml` ONLY while no `config.json` exists; there is **no deep-merge hook** (no root `hooks.py` yet). Safe today because `api/config.py` persists the FULL merged dict on first save (all keys present afterwards) — but a hand-written partial `config.json` would make runtime paths lose every unwritten default. Adding a `get_plugin_config` hook (deep-merge defaults UNDER config.json, the `_model_fallback`/watch-skill pattern) closes this.
- **Nudge delivery** is `context.communicate(UserMessage(...))` — asynchronous injection into the chat's loop; there is no `agent.memory` on the base framework.
- **Stall detection** keys off `context.last_message` (ISO string) + the last `response|tool|user|error` entry in `context.log.logs` (accessed under `context.log._lock` — private attr, wrapped in try/except).
- **error.txt** at `usr/chats/<chat_id>/error.txt` is the framework's crash marker; presence ⇒ `error` status even with no live context.
- **API handlers**: `class X(ApiHandler)` + `async process(self, input, request)`; routes are `/api/plugins/chat_shepherd/<file basename>` (POST + CSRF by default — the WebUI uses `fetchApi`).
- **State** is `data/state.json` (gitignored): nudge counters reset to 0 whenever a chat is seen `running`/`awaiting_user`/`paused` at tick end, so the 3-nudge budget is per-stall, not lifetime.

## Known limitations (flagged, not fixed)

- `tick()` runs synchronously on the event loop (blocking `state.json` I/O + log scans). Small files today; offload via `asyncio.to_thread` if chats/history grow.
- `watch_all: true` is accepted in config but the tick does not yet honor a per-chat watch list.
- No root `hooks.py` (no `get_plugin_config` deep-merge hook, no uninstall state cleanup) — see Local Contracts.

## Verification

- `GET/POST /api/plugins/chat_shepherd/status` returns live classified chats + counts + config snapshot.
- Sidebar shows per-chat icons; dashboard `webui/main.html` shows counts + history; manual Nudge increments the counter, Resolve resets it, Dismiss removes the entry.
- Settings → Plugins → Chat Shepherd card saves through `api/config.py` (clamped, known-key-only).
